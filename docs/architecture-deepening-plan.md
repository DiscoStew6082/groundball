# Architecture Deepening Notes

This file replaces the earlier Chroma-era architecture plan. That plan has been retired because Chroma-backed player biographies duplicated generated facts, required rebuildable local vector state, and made biography behavior depend on fragile corpus/index availability.

Current architecture direction:

- DuckDB is the source of truth for structured stat and freeform database answers.
- Player biographies are generated by the local LLM only after DuckDB resolves a single player identity.
- The biography LLM contract returns prose plus extracted `stat_claims`.
- Supported career and season stat claims are verified against DuckDB.
- Contradicted or unverified biography stat claims keep the generated prose but add structured warnings and a visible answer note.
- Stat explanations such as "what is OPS?" are open LLM explanations, not Markdown or vector-index retrieval.
- Checked-in corpus Markdown remains useful project material for docs/tests, but it is not runtime grounding.

See [architecture.md](architecture.md) for the current runtime overview.
